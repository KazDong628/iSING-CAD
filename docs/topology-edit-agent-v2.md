# 局部拓扑编辑 Agent、几何执行器与评估 Agent

## 目标

旧规划阶段只能在一组预生成候选中选择，无法表达“`g002` 到 `g004` 实际应为一条圆弧”这类局部结构修正。新闭环允许多模态模型诊断碎线和错误分段，但数值几何始终由本地内核从原始分割边界计算。

## 三个职责

1. **局部拓扑编辑 Agent**查看原图和带编号的候选叠加图。它最多提出三项操作，每项只能引用 2–6 个按轮廓顺序连续的现有图元 ID，并从 `merge_chain_as_line`、`merge_chain_as_arc`、`merge_chain_best_fit` 中选择一种。它可以引用现有 OCR 记录 ID 作为证据，不能产生坐标、半径或尺寸值。
2. **本地几何执行器**把指定链定位回分割原始边界，拟合 LINE 或 ARC，重建共享节点、图元顺序和关系。每项操作产生一个可审计候选；多项互不重叠且不跨循环起点时，额外产生一个同时应用全部修正的组合候选。每个候选必须保持闭合、连续、简单且只含 LINE/ARC，并通过原图笔画支持和边界偏差预算。
3. **独立评估 Agent**在原候选和本地有效编辑候选之间选择。它只接收候选 ID、本地指标与渲染图，不能修改几何。即使它选择编辑候选，本地门禁仍要求分数和边界支持不显著下降、无支持对象数不恶化超过限额，而且对象数确实减少。

任何阶段失败或弃权都会保留原候选和已生成产物。API 成功只表示传输和结构有效，不表示尺寸正确或与 GT 一致。

## 数据边界

- 请求中不包含 GT、参考 DXF 或评估对齐结果。
- 编辑 Agent 只看到实体 ID、类型、有限 OCR 证据和两张图；不发送已有 CAD 坐标。
- 坐标、圆心、半径和端点由本地几何执行器计算。
- 评估 Agent 与编辑 Agent 是两个独立请求，各自保存状态、耗时和通过结构校验的可见回答。
- 聊天界面展示观察摘要、操作、候选决策和证据标签，不保存或展示模型私有思维链。

## 产物

`topology-edit-proposals.json` 保存编辑回执、本地执行审计、独立评估回执及最终接受门禁。编辑候选会写入 `topology-candidates.json`，对应叠加图命名为 `topology-candidate-cand-edit-*.png`。若编辑被接受，`topology.json` 和 `topology-overlay.png` 发布选中的本地几何结果，之后才进入标注绑定和参数化求解。

## 已覆盖的回归条件

- 未知、重复、非连续图元 ID 被拒绝。
- 模型输出坐标或额外字段被拒绝。
- 多处互不冲突编辑可形成一个组合候选；重叠或跨循环起点的组合只拒绝组合项，单项候选仍保留。
- 编辑不原地修改基础候选。
- 编辑后的图元仅为 LINE/ARC，端点共享并保持闭合。
- API 请求不发送 GT 或现有 CAD 坐标；无密钥时不读取图像也不发起网络请求。
