# 源图约束驱动的局部重建

本次升级保留 GitHub `v2`（`85e2256`）作为修改前基线。训练数据和 GT 坐标不参与预测。人工修正掩膜的案例属于开发回归，不能当作无人干预、独立保留样本的准确率。

## 处理顺序

1. 分割并等待人工审核；审核通过后保留模型原始掩膜、修正掩膜及哈希。
2. 生成源图支持的 LINE/ARC 拓扑候选。
3. 独立检查标注关联和水平、竖直、相切证据，进行本地约束试算。
4. 局部编辑 Agent 读取原图、候选叠加图、标注局部图和上轮公开诊断，提出对象 ID 与编辑操作。
5. 本地几何执行器构造候选；独立检查闭合、自交、源图支持、原有约束是否丢失及联合求解是否可行。评估 Agent 只能选择通过本地检查的候选。
6. 最多三轮；新提案被拒绝时允许根据拒绝原因改提案，重复提案、重复几何、模型弃权或预算耗尽时停止。每轮单独保存。
7. 在线绑定与本地数值求解后，再检查源图笔画支持、已构造半径是否保持以及 DXF 回读。失败保留上一套有效草稿。

## 几何执行能力

- 合并连续图元为直线、圆弧或本地选择的最佳原生图元。
- 用原图标注指导圆弧重拟合；拟合不出指定半径时明确保留未解决状态。
- 将单个误判的圆弧重拟合成直线。
- 按原始边界特征重分段为最多四个 LINE/ARC，并移动局部连接位置。
- 在有明确方向箭头、目标位置和源边界支持时，构造指定半径的 LINE/ARC/LINE 相切圆角。

当前精确圆角构造适用于两侧直线的角部。任意圆弧与圆弧、直线与圆弧组合的圆角尚未全部覆盖，不使用任意曲线或贝塞尔曲线掩盖失败。增加图元需要局部特征证据，不能仅凭模型意见通过。

每个图元带有稳定身份及父对象记录。`g000` 等显示编号只在某个候选版本内有效；跨轮次查找应使用 `stable_id` 和 `entity_identity.parent_to_current`。

## 约束与精度的区分

结构关系既要符合候选拓扑，也要在原图中得到独立支持。水平、竖直候选需有覆盖足够长度且不歧义的轴向线迹；相切候选需有连接处两侧可靠的线迹方向。API 不可用时，符合相同检查的关系仍可本地进入求解。图像缺少证据时保留未绑定，不强制把所有连接处变为相切。

上游引线可以作为下游复核的候选，但必须重新核验文字、方向箭头和目标位置。精确构造出 R3，不意味着已经证明该位置确实对应 R3；`radius_constructed` 与 `dimension_bound` 分开。数值求解成功也只说明已绑定约束子集满足固定容差。

聊天和工作台展示每轮提案、拒绝原因、接受结果、已执行约束、残差、未绑定标注和剩余自由度。这些是可审核输出，不是模型私有思维链。

连接处较大的切向跳变还会作为最多十二条 `review_items` 传给后续编辑 Agent。它们是复核线索，不计入失败问题数量，不自动触发相切约束；设计直角必须保留。Agent 需结合原图判断连接是否应当平滑。

## 审计文件与复现

新增 `topology-iterations.json`、`reconstruction-feedback.json`；每轮文件在 `topology-iterations/round-*`，约束试算在其 `constraint-preflight/` 子目录。最终 `validation.json` 包含逐对象方向和连接处切向夹角诊断，角点不自动判为错误。

已审核任务可在新目录重放，不覆盖原任务：

```powershell
python scripts/replay_reviewed_case.py JOB_ID --output runtime/replays/new-local-run
python scripts/replay_reviewed_case.py JOB_ID --output runtime/replays/new-online-run --online --provider-profile 9ecode-gpt-5.6-sol
```

脚本使用只读数据库连接，冻结原图、OCR、审核掩膜和原产物；比较报告区分几何有效、求解状态、已绑定约束与分割边界偏差。分割 IoU 不是 GT 精度。在线请求上限默认 600 秒，显式环境设置仍可覆盖；每次调用有总时间边界。

CL60 的固定 20 图元对照显示：新增源图验证后的两个水平关系和一个竖直关系，约束数由 2 增至 5；两个原有高度继续满足，左壁和两个平台的方向得到修正。半径与部分相切证据仍不足，不能宣称尺寸全部恢复。完整流程可能选择不同的对象分解，需与固定拓扑实验分开比较。
