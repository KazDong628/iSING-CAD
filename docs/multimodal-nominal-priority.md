# 半径与斜线角度优先的多模态迭代

已核实的圆弧半径和单斜线角度优先绑定，并作为精确数值约束进入联合求解。拟合形状是初始解；后续通过调整未知圆心、切点、线段长度和相对位置消除其他误差。已绑定的数值不能随优化漂移，也不能用自由拟合圆弧替代未完成的标注。

## 本轮改进

- 增加 `angle_target_provider.py`：原图加带源像素刻度的局部放大图，在线模型识别角度基准线、有限斜线、双箭头及可见角度文字。只接收原图像素提案，不接收模型生成的 CAD 参数。
- 模型点位作为局部搜索窗口。通过有界原分辨率直线检测吸附到真实笔画；不能把几像素的定位误差直接当作没有这条斜线，也不能将模型拟出的圆弧弦直接当作斜线。
- 候选仍须通过原图双箭头、轴向基准、有限 LINE 归属检查。角度值来自标注，像素斜率只作粗分支和支撑检查；ARC 上的角度证据用于恢复 LINE，不能直接对 ARC 绑定斜线角度。
- 已恢复的短 LINE 在求解后可能移动端点。新路径按当前原图重新观察其完整有限支撑和双箭头，不因旧端点快照失配而永久失去角度候选。旧元数据本身不能替代新证据。
- 标注优先模式的 API 分页先检查半径、角度，有限的放大图优先展示尚未解决的关键属性；所有其他已识别尺寸继续计入覆盖分母。
- 最终以原生 DXF 回读的半径、角度及相切方程判断，不能用模型“通过”的回答或 overlay 外观替代。
- 角度定位遇到连接超时、传输或 HTTP 失败时，在同一总时限内最多尝试两次，逐次保存记录；失败不能清空原有提案和有效 CAD 草稿。没有角度记录的任务不触发此接口。
- 同一角度同时提供上下文原图和局部放大图，记录精确的像素映射。格式正确但笔画支撑失败的模型提案，会收到原提案与失败原因，最多重读一次；两次请求共用一个时限，不把重读成功当作绑定成功。
- 新提案校验失败时，仍独立检查相同原图上的已有提案；此前有证据支持的定位不会被一次较差的新回答覆盖。回执分别记录本次 API 的定位与保留的旧定位，不能把旧证据算作新调用成功。
- OCR 数值暂时禁用，不代表它的文字笔画消失。所有原图文字区域仍用于几何检测时的遮蔽；存疑数值继续禁止绑定。044 的 r024 此前被整条排除，导致附近文字干扰 r032（24°）的直线与箭头检测，这两项职责已分开。
- 标注优先模式的规范初次联合求解也加入原图笔画软观测。此前只有最长 15 秒的可选重启使用它，容易出现数值等式已经满足、原图支撑却未改善的情况。原图支撑恢复现在可以使用同一轮剩余的 120 秒／30000 次总预算，半径、角度、相切等约束及原验收阈值均保持不变。
- 恢复已有精确解时，CAD 对象、节点身份、节点 x/y 等仍逐项精确一致；只有由仿射变换推得的 `source_px` 缓存允许不超过 `1e-7` 像素的数值舍入。实际案例中缓存只相差约 `1e-11` 像素，原字节哈希却误判为换了一个解。真实 CAD 坐标即使只有 `3e-11` 的变化仍会拒绝，参考评估阈值没有变化。

## 为什么不能保证单纯无限迭代必定成功

正确对象数量和类型是必要条件，还需要正确的对象顺序、圆弧分支、标注归属、角度基准、相切方向，以及足够独立的尺寸。缺少这些信息时，问题可能有多个解或仍有形状自由度；错误绑定会造成冲突。数值求解器只能求解已经正确表达的方程，因此迭代需要在语义与离散拓扑修正、精确约束求解之间交替进行，并保存可回退的有效解。

在联合问题中，已绑定 `R` 是圆弧参数化中的固定常量，不能作为自由拟合量继续漂移。单斜线角度由角度方程与最终原生坐标回读认证；圆弧与相邻线的相切要求切点半径向量与线方向正交，两个圆弧还须满足正确的切向方向。未知的是切点、长度、未标注圆心/位置等。若标注实际指向一条 LINE，而当前只有一段 ARC，就先修正类型与有限区间，再绑定和求解；给错误对象反复施加权重无法补出正确的离散拓扑。

044 的 R6、R16、R13 未完整表达在旧的简化参考闭合中。本轮继续将它们列为待完成标注，不能用删去这些义务的方式宣称全部半径通过。源图义务与旧 GT 一致性分别报告，GT 数据保持只读；参考 DXF 仅用于预测冻结后的独立评估。

## 实验范围

`runtime/cad-controlled-20261008/multimodal-nominal-v59-probes/` 是两次源图角度定位探测，随后对相同在线提案做离线像素复核。初始提案有像素误差，初次严格像素筛选未通过的结果仍保留。补充本地吸附和有限对象复核后，HDSA 的 r035 → g002（12°）、044 的 r032 → g001（24°）成为可绑定候选；这不等于最终求解或 DXF 已通过。

V59、V60 的正式重放暴露了已有解缓存误拒绝的问题，未进入新的联合求解，不能算完成角度绑定。V60 的两次新角度定位都成功传输并通过格式检查，但新像素提案没有通过局部笔画校验；它们仍保留为失败的定位尝试。V61 首次启动时冻结目录缺少评估脚本，两次启动失败也保留，不以随后的修复覆盖失败记录。

V61b 的 HDSA 数值候选已满足 12 个半径和全部 4 个斜线角度，但源笔画支撑比例由约 0.946 降到 0.856，超出原定允许下降 0.035；两次短重启未恢复支撑。因此候选没有替换已有 DXF，最终发布仍为 12 个半径、3 个角度。不能将候选的 4 个角度数值通过说成最终 DXF 已通过。V62 根据这个失败继续改进求解过程，并在报告中单独展示最后数值候选与最终发布。

## V62–V64 实际结果与继续优化

V62 对两个案例重新调用在线 API 执行最终阶段重放。HDSA 最终发布为 12/12 精确半径、3/4 精确角度，原坐标最大误差约 1.053269 mm；044 最终发布为 10/13 精确半径、4/4 精确角度，原坐标最大误差约 1.975163 mm。044 的 24° 已实际进入发布 DXF，不能只报告角度定位成功。两图的完整源标注目标及完整 GT 目标均未通过；HDSA 的最后数值候选有全部 4 个角度，但完整原图支撑失败，未替换正式结果。

V63 单独测试了固定在线绑定后的离线数值继续优化，没有再次请求模型。HDSA 的原生候选保留 12 个半径和 4 个角度，冻结后独立 GT 评估最大误差约 0.660222 mm；044 保留 10 个半径和 4 个角度，最大误差约 1.861869 mm。HDSA 的完整源笔画支撑检查仍失败，044 仍超过 1.5 mm，不能把这些结果称为新增在线成功或全部通过。

V63 诊断脚本把展开的优化域误传给辅助求解器作原图比较基线。脚本最终的独立完整源图检查仍正确拦住 HDSA，未发布这个候选；V64 改为传入完整恢复图，再在辅助求解器内部提取不可变优化域。历史记录不改写，报告明确披露这一限制。

V64 的补充改进：

- 标注优先模式中，若掩膜是尖角，但原图有已验证的圆角箭头，可从两条既有有限 LINE 构造精确标注 R 的 LINE/ARC/LINE 初始解。R 不由像素拟合决定；两条支撑线的方向和外端点保留，构造不能吞掉有限 LINE。
- 物理箭头尖端与投影到旧掩膜边界的足点分别保存。缺少圆角时，旧边界上的投影位置不能反过来否决正确圆角。箭头定位使用原有 12 像素关联窗口，并明确不把该窗口当成参考精度阈值。
- 对上述特殊构造，重新检查当前原图的圆弧和两侧有限线笔画、全局箭头归属、标注值与精确几何相切。采用已有局部接触候选的笔画门槛，不能由构造元数据直接认证，也不能再次用掩膜尖角来认证圆弧半径。完整源图、联合方程和 DXF 回读门槛继续独立执行。
- 两个父 LINE 共用一个替换链时，只有唯一共线、方向一致且保留原外端点的有限后代才能继承原 LINE 的角度与支撑线尺寸。被裁掉的旧拐点不会自动变成新切点；端点尺寸须重新建立正确锚点。
- 原图支撑尚未通过、但半径/角度/关系/尺寸的原生 DXF 检查全部通过的改进数值迭代，可单独保存为未发布中间解，并作为下一轮起点。正式替换检查仍保持失败，不能将数值中间解标记成完成，也不能移动原优化域或重设验收基线。

044 的 R6 当前局部绑定候选达到 11/13 半径、4/4 角度，候选由 20 个对象增至 21 个。原 135 mm 支撑线尺寸和水平方向已可正确继承；另一处旧相切关系重新检查失败，因此该拓扑候选尚不能替换正式结果。R16、R13 仍未完成。这些未完成义务继续计入分母。

所有数值继续优化均固定已经核实的标注常量。参考 DXF 只在预测冻结之后用于独立评估，不能用 GT 误差选择数值轮次或给模型提供参数。V64 实验和回归结果见 `runtime/cad-controlled-20261008/multimodal-nominal-v64-review.html`。

V64 的 HDSA 连续四轮原图支撑比例为 0.844845、0.870875、0.875154、0.907954，全部保留 12 个半径、4 个角度和 15 个已绑定相切关系的原生精确验证。第四轮仍低于原完整源图门槛约 0.910902，冻结后独立评估的原坐标最大误差约 0.741388 mm；形状误差通过 1.5 mm，并不代表全部对象参数通过（完整对象参数匹配为 15/22）。044 的同类离线候选最大误差约 1.886869 mm，仍未达标。

V64b 从第四轮继续的尝试发生原图支撑回退，保留记录并且不替换更好的第四轮。继续运行脚本已补充“原中间解也是候选”的机制：将原解重新核验并记录为 round-00，在同一原图和同一组已知约束下比较新轮次；新轮次较差时保留 round-00。每次新运行保存实际执行的脚本副本及哈希。选择依据为原图和原生约束，不读取 GT 分数。

回归命令 `python -m pytest -q`：2181 项通过、3 项跳过。工作台当前代码另在 `http://127.0.0.1:8770/agent` 启动并验证健康接口、配置接口和页面均返回 200，配置中有 4 个提供商选项。原 8769 进程保持运行；停止并重启原进程的操作被自动审批策略拒绝，因此不能把原 8769 页面说成已加载本轮修改。

## V65–V70：原图观测、局部编辑证据与文字辨认

本轮定位到三个不同环节的缺陷，分别修复并记录实际重测结果：

1. 原图软观测此前可以停在较近的笔画边缘附近，而没有取得完整笔画中心；按圆弧固定采样序号配对，还会把切点移动误当作几何误差。标注优先模式现在沿法向观测完整、唯一且方向兼容的深色笔画带，排除 OCR 遮蔽区和交叉剖面线；计算观测中心到原生圆/直线的残差。观测两侧边缘的窗口可以容纳粗笔画，但允许的中心位移、原求解域及最终原图门槛不变。没有观测的部分仍保留掩膜软定位；像素不会提供新的标注半径或斜线角度。
2. R6 的局部插入会重编号对象，但远处未改变的尺寸和相切关系有时因重复检测没有命中而被清空。新增 `unchanged_source_obligations.py`：逐项核对父检查点哈希、源图哈希、OCR 文本与框、单位、对象唯一身份、未改变的几何、原独立证据及当前原生方程，只保留未改变对象上的旧尺寸与几何关系。它不新增半径或角度归属；新的正向文字/几何矛盾仍会拒绝继承。记录明确标注本次 API 和重复检测没有重新确认，不能把继承算作新在线理解成功。实际 R6 候选已保住 29 项先前义务。
3. V67 的在线模型把左下 R15 读成了 R13，虽然 R6 补入成功，半径覆盖却没有增加。文字不一致拒绝本身是正确的；需要改进输入辨认。V69 的每个绑定分页增加一张原图字形图，为本页全部记录提供带 r 编号的独立像素放大块；编号之外不绘制 OCR 值，完整原图与拓扑上下文继续发送。实际新调用已正确辨认 R15，044 的绑定达到 11/13 半径及 4/4 角度。最终发布结果以运行报告中的原生 DXF 读回为准。

有限窗口的相切检测也增加独立复测：短窗口测得非相切时，用两侧已提供的有限区间分别测量更稳定的原图方向；窗口先按区间长度确定，不能按“哪个结果更相切”选择。最长 96 像素及原 3° 证据门槛保持不变。原生求解后的严格 G1 检查仍使用原来的数值精度。原图检测缺失不代表已经相切，所有未知接点仍单列。

V65、V66 的在线输出没有达到完整目标，失败保留。V66 固定在线绑定后的离线数值试验将 HDSA 原图支撑从 0.907954 提高到 0.909446，仍低于原门槛 0.910902；候选保持 12 个精确半径、4 个精确角度及 15 个已绑定严格相切关系，不能替换正式结果。冻结后独立 GT 评估的保守最大误差约为 1.090522 mm。形状误差通过 1.5 mm 不等于完整参数、标注覆盖或全部接点通过。

V68 对全部对象扩大数值笔画关联的实验反而将支撑降到 0.881084；V70 只对完全缺少观测的对象试验，支撑降到 0.905711。两项改动均未合入当前代码，选择 round-00 保留原中间解；没有使用 GT 误差挑选候选。源图数值优化是本地确定性算法，没有本地 GPT 参与。

V69 全量回归 `python -m pytest -q`：2198 项通过、3 项跳过，保留两项依赖库警告。新增用例覆盖完整原图笔画带、并行笔画歧义、圆弧切点移动、有限窗口复测、父证据篡改/对象变更/新矛盾拒绝继承，以及字形图覆盖全部记录且不根据 OCR 值重绘像素。早期失败测试日志也保留。

本轮共四组、两张开发图的在线最终阶段重放，复用冻结的上游 OCR 与拓扑；不是八张独立图纸，也不是八次全新网页端到端成功。GT 派生栅格掩膜继续作为输入，参考 CAD 坐标不进入预测或提供商。预测冻结后才执行独立 GT 评估，原 0.1 mm、1 mm 和补充 1.5 mm 检查均保留。完整结果及未完成项见 `runtime/cad-controlled-20261008/source-checkpoint-v69-review.html`。
