# HDSA65 与 044 自动重建差异及本轮改进

本报告以冻结的 V11、V15、V16 运行记录和本轮候选代码为依据。新在线试验的最终数字以 `runtime/cad-controlled-20261008/source-generalization-review-20261010.html` 及同名 JSON 为准。本轮仍是原图、OCR、GT 派生的二值掩膜条件下的开发测试，不是分割泛化测试，也不是独立留出集结果。

## 1. HDSA V11 的 completed 并不等于完整重建

V11 的参数化状态主要由半径合同决定。HDSA 的 12 个半径当时全部绑定，因此标记 completed；但同一产物的 `all_dimensions_verified=false`、`underconstrained=true`。044 的半径还未全部解决，因此显示 completed_with_unresolved_radii。两者状态表达的范围不同于用户要求的完整对象、属性和关系重建。

| 冻结 V11 指标 | HDSA65 | 044 |
| --- | ---: | ---: |
| 原生主轮廓对象 | 10 LINE + 12 ARC | 10 LINE + 10 ARC |
| 绑定的已识别标注 | 17/37 | 9/35 |
| 精确半径 | 12/12 | 7/13 个已识别 R 记录 |
| 角度 | 4/4 | 2/4 |
| 剩余形状自由度 | 23 | 33 |
| 配准后保守最大偏差 | 0.460447 mm | 0.449693 mm |
| 1 mm 完整对象参数目标 | 未通过 | 未通过 |

“13 个 R 记录”不是“正确拓扑一定有 13 个 ARC”：重复标注、其它范围的对象及不确定箭头都需要独立判定。对象总数相等也不能证明对象一一对应、半径/角度/端点/圆心/跨度都正确。

候选分支已有更完整的 source reconstruction contract：标注覆盖、关系覆盖、原生 DXF 读回、数值子集、几何合法性和剩余自由度分别检查。它仍不证明全部原图标注已检测，更不等于 GT 精度证明。

## 2. 第一层缺口：在线尺寸解析没有实际修正输入文字

旧 DimensionProvider 接收最多16条 OCR 文字，优先选已有绑定和 R/直径，不接收原图。返回值只记录“与本地解析是否一致”，随后仍把原 document 传给拓扑与绑定。后续视觉绑定如读出不同数字，又被 `source_observed_text_mismatch` 拒绝。因此一个识字错误可以贯穿所有迭代。

直接查看 044 原图可核实：r014 的 OCR 为1135，原图为135±2；r022 为66.85，原图为69.85；r024 为+18，原图为181±1；r026 为4606.038，原图为46.038。这里的核对使用原图，未从 GT 或拟合尺寸倒推数字。

本轮增加独立的原图文字重读：先保存本地草稿，再对未参与当前尺度建立的长度/疑似尺寸进行两次原图裁剪转写。请求只包含原图像素和记录ID，不含原 OCR 数字、CAD属性或GT。两次语义一致才形成有效 OCR 副本；原文件、框坐标和原文保留。已有定标证据所用记录全部锁定，避免文字更改后沿用矛盾比例。恢复、反馈和参数化读取同一个经过哈希和回执验证的有效副本。

真实 V17 在线测试首先暴露了整页结构失败：少数非数值符号会使整页转写丢弃。V18 将长度优先，对合法且完整、无重复ID的响应隔离不可接受的单行；未知ID、重复ID和非法整体结构仍拒绝。API共识是来源可审计的解释假设，不是真值证书；几何关联仍需独立校验。

第二轮审计进一步发现三个缺口，已进入后续定向修复：

- V17/V18转写提示中的具体数值示例恰好包含044待纠正值135±2。两次相同模型调用共享提示，不能称为无偏独立证据。冻结记录保留，后续提示去掉数值示例。
- 去除示例后的真实两视图探针中，原向的69.85、46.038分别被第二视图读为58.69、83.064。第二视图原来固定旋转+90度，对这组竖排文字产生倒向阅读。修复方向应是提供两种源像素朝向而不是根据期望尺寸选择一种。
- 保留旧OCR是必要的可追溯行为，但不能让已出现语义反证的旧值继续被自动锁成硬约束；需要独立的准入状态。同时，有效OCR的身份必须绑定到当前模型和DXF发布批次，仅校验重读sidecar内部一致不足以防止跨轮混用。

## 3. 第二层缺口：尺寸线、测量位置与轮廓节点被混为一谈

原长尺寸检测服务于尺度估计，较大的最短长度限制不适用于10 mm这类短尺寸。外置箭头会让完整笔画长于真正尺寸区间；OCR框也可能覆盖实际尺寸界线，旧“找文字框外的两端”办法会取错跨度。

本轮另建短尺寸绑定证据路径：通过原图上两条界线、同一尺寸线和两个相反箭头确定区间，不用名义值挑选端点。HDSA 的10 mm区间由旧257像素恢复为约56–57像素，25 mm由348.5恢复为141.5像素；044的26和28.57区间也得到修正。原尺度算法不变，竞争区间和搜索截断显式保留为不确定。

但正确尺寸区间不等于已绑定约束。逐端点审计表明，HDSA数处10/25尺寸测量的是斜线内部的截面，而不是端点或圆角切点；044部分尺寸定位曲线截面或轮缘极值。当前节点距离语言无法表达它们。把附近节点拖过来会改变设计含义。

本轮先完成通用理论角点类型：两条 LINE 支撑线的交点作为派生测量锚点，求解时从当前未知端点重新计算，不新增轮廓节点或固定拟合坐标。新增约束、雅可比、秩/自由度、严格验收、恢复以及原生 DXF 读回均覆盖这种锚点。它解决理论尖角尺寸的表达，不能冒充已解决上述截面尺寸。

后续必须增加有明确基准定义的测量站、直线/圆弧与测量站交点、曲线极值、圆心及旋转轴直径站。没有位置定义的辅助站会增加一个未知数；增加一个站再加一条尺寸式，未必降低形状自由度。应计算消去辅助量后的形状秩，而不是用约束条数宣布进步。

## 4. 第三层缺口：主轮廓范围与全部原图标注义务不一致

仅凭原图和当前输入掩膜即可看到：044原图右侧有外轮缘，但当前选定轮廓以直线闭合。R13的真实原图箭头可能指向这个范围之外。旧局部搜索先要求箭头靠近当前图元，再检验笔画，容易先丢掉真实的范围外目标，转而把范围内的剖面线交点当作箭头。

对已冻结预测的后验评估另发现，参考也含 `GT_CLOSURE` 假设闭合线，未包含原图外缘R6/R16/R13。这一信息只解释评估范围，绝不能作为预测中的排除名单。不能一边维持简化主轮廓范围，一边要求完整生成范围外所有对象，再用前一种GT评价后一种任务。

应先独立定位原图箭头，再与不可变输入掩膜范围及任务声明比较，最后匹配候选对象。必须区分：范围内对象缺失、明确范围外、范围冲突/不确定、无法核实箭头。范围外和未知记录保留在全量报告中。仅API说“在外面”或当前拟合图没有对象，均不足以自动排除该标注。

本轮V18增加保守防误绑：独立原图笔画确实支持一个远离输入边界的外侧箭头，而内部候选来自另一条物理引线时，停止对该内部候选的自动半径绑定/插弧，记录范围冲突。不根据案例名、半径值或GT删除义务，也不将范围冲突计作完成。

## 5. 第四层缺口：强约束正确，不代表拓扑和问题本身正确

半径固定仍不能确定圆心、端点与圆弧跨度。相切也需要选择正确对象和正确连接关系。在缺失直线、多个真实曲率段合成一段、标注绑定到错误对象时，加更高权重会把错误问题解得更“精确”。

本轮保留精确R和已核实严格G1/角度；增加派生测量锚点的硬等式和独立导出回读。新锚点尺寸的数值证书阈值为1e-7 mm，旧节点尺寸沿用0.05 mm。原始源图/掩膜偏差门限未调宽。无可行解时保留自动草稿并报告哪条条件失败，而不是宣称该设计不存在可行解。

源图笔画校验也有能力边界：粗笔画、OCR遮挡、尺寸界线与实体间的规范留白都会使“必须一条连续笔画连接”的判据漏检。应重新测量两个共线源笔画及有限端点关联，保留实际间隙；不能仅调宽一个全局像素容差。

## 6. 第五层缺口：搜索循环在不完整的表达空间中重复

V11 HDSA搜索2轮8次预检，044仅1轮3次。每个候选重复原图箭头定位很昂贵；部分旧加时条件要求已认证进步，恰好排除了需要连续数步才能可行的修复。候选分支已允许受限的中间拓扑继续扩展，但它不能创造尚不存在的尺寸类型或修复错误文字。

API绑定器只选择已生成的候选ID。没有正确候选、局部证据拒绝、范围冲突或错误OCR时，即使模型看懂图也无法通过接口表达正确结果。这是系统接口与约束表示能力的限制，不能由HTTP成功率推断模型具备完整重建能力，也不能用人工交互GPT完成的GT作为同条件API对照实验。

## 7. 建议的后续验收顺序

1. 明确输入主轮廓范围与闭合假设；分开报告检测到的全部标注和本范围可求解义务。
2. 原图OCR解释、来源箭头、范围归属、对象绑定分别持久化，原文和拒绝原因不可丢弃。
3. 先建立测量图，再与实体拓扑共同求解；实现基准、直径站、截面和极值，不能全部映射到轮廓顶点。
4. 对每种“未解决”生成有针对性的候选动作；文字/范围问题不触发盲目拆弧，未知尺寸类型不靠加迭代轮数补救。
5. 精确半径、角度、切向、闭合、退化、自交、源图支撑、形状自由度分别验收；冻结后重新读取DXF检查。
6. 在同样源输入和固定比较器下同时检验HDSA与044，并保留失败轮次、API失败和范围不一致记录；不能只展示最好的overlay。

完整目标目前仍未达成。本轮测试用于确认具体缺口和验证修复范围，不把“修好某个接口”“尺寸识别更多”或“轮廓小于1 mm”写成完整自动CAD重建成功。


## 8. 本轮修复后的边界与下一步顺序

V19修复了可定位的软件错误：单向旋转导致竖排反读、整页转写被单个符号拖垮、有反证的旧值仍能锁定、重读与发布CORE没有共同身份。短尺寸与理论交点也已进入候选生成/求解/原生读回。它们不能替代尚未实现的测量图。

当前仍不应扩大在线调用预算来掩盖以下缺口：

| 优先级 | 缺口 | 应实现的机制 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 主轮廓与外轮缘范围冲突 | 按任务/输入范围明确目标，源箭头独立定位后分类，所有范围外/不确定记录保留 | 同一输入范围的GT评估，与全部源标注审计分开 |
| P0 | 源测量位置不是轮廓节点 | 测量图：有定义的基准、截面站、LINE/ARC交点、圆心/极值、直径轴站 | 原生DXF独立重算测量值；消去辅助量后报告形状DOF |
| P1 | API箭杆端点粗糙造成局部定位无法启动 | 对短/退化方向提示另生成有界的原图笔画假设，再独立验证箭头、整杆、文字归属；不能仅降低箭头证据阈值 | 真/假箭头正反样本，完整候选竞争和截断状态 |
| P1 | 拓扑修改破坏邻接或遗漏小斜线 | 根据角度/圆角关联提出局部 LINE—ARC—LINE 等组合编辑，保留先前已认证子结构，多步后联合求解 | 每个标注属性和接点读回；对被替换对象做继承审计 |
| P1 | 求解空间表达不完整 | 离散拓扑候选与连续参数联合搜索，显式诊断欠约束/矛盾/局部最优 | 准确对象对应、R/角度/G1、原图证据、闭合与自交、DOF分别通过 |
| P2 | 定标文字被锁定后无法纠正 | 单独的尺度假设重建流程；先重算尺度、再重建候选与所有坐标映射 | 不允许修改定标文字却沿用旧尺度 |

“优化器收敛”只说明它停止在当前数学问题的一个解/驻点。错误OCR、错误对象范围、错误绑定或缺失测量类型，都可能让它稳定地给出错误CAD。全局切向/角度要求更严格后，旧几何初始化不再容易通过，这是本轮暴露的约束覆盖问题，而不是放松公差就能解决的问题。

人工交互式GPT制作GT与这里的API系统不是同条件对照：前者可以反复查看整图、自由改变对象表示并做额外推理；API绑定接口只能选择库存中已有候选ID，且本地执行器仍需能表达并求解该动作。对比应冻结相同输入、工具、轮数、预算和独立评估，再判断模型因素。

V18线上R13范围保护尚未生效：该次API给出的tip/shaft仅相距约4.47像素，独立定位记录invalid_source_input；内部笔画竞争仍生成错误拓扑义务。离线使用足够完整的原图提议时保护通过，不能把离线成功写成该次线上范围问题已解决。正式导出也未接受对应错误R13数值约束，二者必须分开。

## 9. V19 最终冻结结果与代码验证

V19 两幅图均完成完整在线管线及冻结后的独立评估。044 发布了参数化子集；HDSA 候选未通过源图预算，保留自动拓扑草稿。完整重建目标仍为0/2。

| 当前正式导出 | HDSA65 V19 | 044 V19 |
| --- | ---: | ---: |
| LINE / ARC | 12 / 9 | 11 / 9 |
| 正式绑定 / 已识别标注 | 0/37 | 8/35 |
| 精确半径认证 | 无正式证书 | 5 |
| 严格角度 | 0/4 | 2/4 |
| 已声明且严格满足的G1 | 无正式证书 | 5/5 |

| 配准后保守最大轮廓偏差 | 0.615310 mm | 0.653195 mm |
| 完整对象/属性/关系目标 | 未通过 | 未通过 |

HDSA失败候选有10/37标注绑定、19条约束、30个剩余形状自由度；它的6个半径、3个角度、3条G1不能计入正式草稿。其掩膜偏差1.568341 mm超过冻结预算0.669669 mm。044发布候选的掩膜偏差0.806467 mm小于预算0.826604 mm，但27条标注未绑定，对象类型数量不正确，独立GT偏差也大于V11的0.449693 mm。本轮因此不自动替换稳定主工作区。

044的V19原图重读实际修正1135→135±2、66.85→69.85、4606.038→46.038。其中135进入正式距离约束；69.85虽有API选中的候选，仍因独立来源证据不足而拒绝；46.038缺少几何候选。r024两次转写不一致，旧值被暂停硬绑定。两幅图的重读阶段均4/4 HTTP和结构校验成功，不能将其写成尺寸绑定或CAD准确率。

本次R13范围保护确实生效：r028独立原图箭头定位成功，目标距输入掩膜约103.327像素，超过24像素范围阈值；错误内部箭头及要求给内部LINE插入R13的义务已清除。R13仍计入未决记录，没有授予范围外豁免。V18失败记录保留，不用本次结果覆盖。

候选代码全套回归为1704 passed、3 skipped，git diff --check通过。V19冻结后补充了有序测量锚点的约束签名校验，防止错误端点的通过回执被复用；此补丁通过全套回归，未再整轮调用在线API。V19两幅图均未使用新anchors约束，因此该差异不改变上述在线结果的判定。

输入、代码快照、冻结DXF和回执、评估前后产物哈希均通过检查。所有在线结果来自原图、OCR及授权的GT派生栅格掩膜，GT DXF仅用于冻结后的评估。本轮是同两幅开发图的重复实验，不是独立留出集泛化结论。
