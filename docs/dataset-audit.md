## 不能当作真值认证的历史信息

`vis/splits.json` 共 42 个参考匹配，记录旧栅格流程的 1 个 accepted、38 个 low_quality、3 个 failed。这个结果包含图像配准和栅格算法的影响，不能直接证明 DXF 对错；新目录会保留原状态，但不把它转换成当前成功/失败判定。

`manifests/native_gt_review_queue_v1.json` 明示 `inventory_only_not_gold_certification`，19 个候选属于待审核库存。候选清单及其哈希不能替代尺寸绑定、主边界范围、建模假设的审核。

历史 `train/val` 分组不用于本次泛化结论。293 已用于模板校准，因此固定为 calibration，不能再称 held-out。其余 49 张保留为 holdout，但当前 unsupported。只在 293 上得到几何通过，不构成对其余图纸的泛化证据。

## 参考中的建模假设与范围

- 293 的参考 JSON 明示未标注拟合桥接圆弧（`fitted_unlabeled`），README 说明踏面采用简化外侧站位。该 DXF 的所有 21 个实体都位于 `GT_MAIN`，不能只凭图层区分哪些部分属于工程尺寸真值。比较所得全轮廓误差只能表示“与该参考重建的差异”。
- 多个参考有 `GT_CLOSURE`、`BENCHMARK_CLOSURE`、`GT_TREAD_SIMPLIFIED` 等闭合或简化层；CL60/HDSA65 还带 `GT_MEASURE` 等测量辅助线。构造及测量线不属于主轮廓评分。
- 188、253 另有 `scored_only` 参考；247 另有 `strict_body_LINE_ARC` 参考。这类文件是部分边界，不能用于宣称完整封闭轮廓通过。
- 269 的主 DXF 含左右两组镜像层，不能未经声明就只取其中一侧以降低误差。
- 若同一样本同时有 design nominal 和 benchmark midpoint，选用版本必须固定并记录；不能在看到预测后挑选更接近的版本。

## 实现中的独立评估

运行时 `dataset.py` 只建立参考文件库存，不读取参考坐标；`read_ocr()` 只读取输入 OCR，剔除任意额外字段与历史机器路径。几何求解器和 provider 不应导入评估模块。`evaluation.compare_dxf()` 是唯一需要读取预测及参考 DXF 坐标的独立评分入口。

比较使用毫米工程坐标，不通过平移、旋转、缩放或最佳配准掩盖尺寸/位置误差。由预测和参考双向采样，再计算采样点到精确 LINE/ARC/CIRCLE 的最短距离；LWPOLYLINE/POLYLINE 拆为其实际直线/圆弧。输出双向最大误差、RMS、长度差、单位信息、纳入/排除图层及采样上界。采样步长至多为容差一半，通过判断还加入半步长的保守误差界。

相同实体数量、坐标接近某一条参考边、重复绘制相同曲线，都不能独立获得通过。数值比较同时检查双向距离和总长度差。非平面、非有限数、零长度以及未实现的几何类型会明确报告问题，不忽略后继续给成功。

默认的全主轮廓指标保留闭合/简化假设层，并明确报告。另给出排除这些命名层后的单向参考覆盖误差，但该指标不会惩罚额外预测边，因此明确禁止用于替代完整轮廓成功判定。部分参考即使局部完全一致，`passed` 仍为 false；局部结果写入 `scope_geometry_match`。

`summarize_evaluation()` 分开统计传输成功、参数准确率、数值几何有效率、参考匹配率、人工确认次数、模板覆盖率与全自动成功率。没有独立标签的参数准确率为 null，而不是 100%。缺失结果、unsupported、missing GT、人工处理均保留在总分母；人工确认后的完成不计全自动成功；校准和保留集单列。

## 校验

`python -m pytest -q tests/test_dataset.py tests/test_evaluation.py` 验证了确定性库存、50 个实际 OCR 文件、路径越界拒绝、来源 id、非有限坐标拒绝、实体顺序/方向无关、同数量但错误位置/半径识别、构造测量层排除、重复曲线识别、部分参考不冒充完整通过、unsupported/人工/未运行保留分母。

当前库存审计和评分器测试没有访问外部 provider。线上传输和端到端系统验证应由实际运行报告另外证明。
