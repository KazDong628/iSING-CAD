# 折线引线与未知过渡圆弧

## 半径来源证据

API 仍只返回原图箭尖及引线上的像素点，不返回 CAD 圆心或未知半径。带折点时，prompt 要求轴线点位于最终通向箭头的直线段。旧格式兼容，像素坐标、字段和记录预算检查保持不变。

当直引线核验失败，`source_leader_paths.py` 在原图的有界窗口中检测一个折点的候选。检测最多 2048 个局部 Hough 段、两侧各最多 64 段、最多 64 个路径候选；超过预算保留未知。候选须核实标签侧段和箭头侧段，各段笔画支撑比例仍至少为 0.88，仍检查最长无笔画间隔、实心箭头锥形和箭尖位移。原图线段可以给出投影点或实测端点，箭尖移动范围沿用直引线的限制；API 提案有纵向误差、Hough 又停在箭身后端时，两者都计入预定位窗口，但最终箭尖仍须在原有位移范围内，且通过完整像素校验。

文字归属使用标签侧段，目标关系使用箭头侧段。两段都重新测量原像素，整个折线路径都检查首次轮廓交点；其他文字对同一物理箭头的竞争仍由原来的全局归属检查处理。折线不是放宽原笔画阈值的理由。

追加在线定位前，已存在的像素提案先在当前原图上复核。仍有效的旧提案得到保留，失败的旧提案可以被新的有效提案替换；来源缓存不直接成为标注绑定。

## 拓扑候选与未知属性

`split_chain_at_source_features` 原来只要一条 ARC 通过像素拟合阈值就拒绝继续拆分。现在允许比较一个有界的两 ARC 解释：两侧均须存在超过观测底限的曲率、足够长的源路径支撑，并使按弧长加权的最大残差平方指标下降至少 75%。它只是一个候选，不自动更改对象数。

两个已验证的 R 标签也不意味着中间只能有两个对象。当严格的双圆弧解释失败时，多半径分段器会有界搜索一个未标注的 LINE 或 ARC 过渡。中间源路径足够长并通过较严格的直线解释时保留 LINE，只有弯曲路径才提出 ARC；两端标注 R 仍作为常数，未知属性仅作为求解初值。桥接不能吞掉任何已验证箭尖，并经过整个源路径的双向密集距离校验。已有原图直线见证被丢弃的编辑候选在进入绑定前拒绝。

所有新候选仍需要重新绑定、保留既有的类型化约束、联合求解、原图校验及 DXF 原生回读。不能用独立 GT 对象数量或半径选择候选。
