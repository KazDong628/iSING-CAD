# 像素分割标签审计

2026-09-20，只读检查现有50张原图、`vis/labels`、划分文件及GT来源说明。逐图尺寸、掩膜编码、配准状态见 `runtime/segmentation-label-audit.json`。未修改 `__dataset`，未下载模型、训练或调用API。

**目前可直接作为可信、人工验收像素监督的标签为0套；技术上可加载的自动派生弱标签为42套。** 可以启动明确标注为弱监督的训练管线，不能据此宣称已有可靠像素精度验证集。

42套的84张PNG均为原图尺寸的灰度二值图，像素值0/255，没有尺寸不一致；`gt_px.npy`是浮点坐标数组，不是人工多边形标注格式，未验证其点序构成正确闭合环。原图从929×508到11336×5668，不能统一缩小后仍声称细线像素精度。尺寸匹配只能证明画布一致，不能证明轮廓配准正确。

`vis/README.md`明确记录生成过程是“GT main-profile DXF registered to origin images via hatch guidance”。`vis/splits.json`中252虽标记accepted，`iou_vs_hatch=0.7075`、记录的`align_err_px=761.10`；后者是旧生成器指标，不能解释成人工测量的实际边界误差。目视检查252叠图仍可见辐板曲线偏移和轮缘/踏面简化；293也有轮毂整体偏移与矩形化踏面。因此即使唯一accepted标签也只列为弱标签候选。

GT几何同样有范围限制：293的 `README_GT_v4.md` 优先尺寸及相切构造；200的 `CORRECTION_v2.md` 声明踏面细节在benchmark范围外并采用简化闭合；187的重建说明使用英寸且部分未标半径来自栅格拟合。190说明含个例栅格配准公式，但不能推广为全部精确配准。`native_gt_review_queue_v1.json`的19个gold_candidate仍全部为未填写人工review decision，清单自述 `inventory_only_not_gold_certification`，不是人工像素真值证明。

旧划分seed42把`iou_vs_hatch>=0.45`的12张分成9训练/3验证，其中11张本身为low_quality。这个IoU比较对象是自动提取的剖面区域，不能当人工mask IoU。旧划分不宜用于报告真实分割准确率；旧记录中的绝对路径还指向`DxfDesign-main-v5`，读取应按当前case ID安全重定位。

`vis/preds/044-main`和`vis/preds/000252`的报告明确来自已有SegFormer预测；当前`runtime/**/material-mask.png`也是算法产物。它们可以作为审阅对照或显式伪标签，**不能改称人工真值**。GT的预览/叠图、OCR可视化也不是独立语义标签。

建议先预测“材料区域”这一二值目标：区域内部即使有剖面线或文字仍属材料，提取区域外边界即可减少内部线条干扰。将精确外边界作为辅助标签；不确定遮挡处设ignore区域。若要分别识别文字、箭头、尺寸线和剖面线，必须补充相应类别标注。

划分应在训练前固定：同一原图的裁剪、旋转、分辨率版本、GT修订及其ZIP/解压副本必须在同组，所有patch和增强继承原图组。相似家族需标题栏图号、型号或记录过的目视比对支持，不能按数字文件名相近就认定同家族。完成分组后可按约70%/15%/15%分训练、验证、内部测试；小组数量不足时按整组调整。弱标签仅进入训练，验证/测试组应先由人校正并复核原分辨率mask，保存原图与标签哈希、版本、审核人和配准变换。

**现有50张都曾被开发流程查看或用于评估；此后在它们上建立的划分只能称内部开发验证，不能称全新盲测。** 真正盲测需要另收未见过的独立图源/家族。新标签与审核记录应写入版本化输出目录，保留原始`__dataset`只读。
